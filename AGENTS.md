# Noyau Rules

- Caveman full responses.
- Every change bumps SemVer in `package.json` and `package-lock.json`.
  - PATCH: fix, style, docs, tooling.
  - MINOR: backward-compatible feature.
  - MAJOR: breaking behavior/data/API.
- Keep `/version.json` and Réglages version display working.
- Run `npm test` and `npm run build` before commit.
- Conventional commits. No AI attribution/co-author.
- Never commit `.data`, secrets, certificates, logs, caches, or build output.
- Inter-agent Claude Design : si demande design/UI/UX/images via Claude Design, déléguer directement via `node scripts/claude-design-tool.mjs "DEMANDE"`.
- Inter-agents Noyau : pour créer un agent, lister les agents actifs, lire leur contexte, leur assigner un projet, les arrêter ou transmettre des messages/tâches à un autre agent, utiliser `node scripts/noyau-agent.mjs [create --name <nom> --prompt <tâche> | assign <agent> <projet> | stop <agent> | list | read <nom> | send <nom> <message>]` (ou skill `noyau-agents` / `noyau-agent-create`). Par défaut, un agent créé hérite du projet et de la permission yolo/dangerous. Ne jamais dire qu'un agent n'existe pas sans avoir listé via cet outil.
- Fichiers partagés Noyau & Livrables :
  - Déposer dans les Fichiers Partagés tout livrable destiné à l'utilisateur : builds/binaires (APK, IPA, AAB, archives ZIP), images, vidéos, maquettes, PDF, exports CSV, présentations ou tout fichier demandé via `node scripts/noyau-file.mjs put <chemin-source> [nom-destination] [projet]` (ou copie dans `$(node scripts/noyau-file.mjs path [projet])`).
  - Ne jamais envoyer de chemins locaux inaccessibles (`/tmp/...`, `file:///...`) à l'utilisateur : déposer dans les Fichiers Partagés et confirmer le nom du fichier dans la section « Fichiers » du projet. Mentionner systématiquement le nom exact du fichier déposé (ex: `coffre.png`) dans la réponse finale : Noyau génère automatiquement une carte d'aperçu direct en un clic dans la conversation.
  - Le code source du projet s'écrit directement dans le dépôt Git (sauf demande explicite de l'utilisateur).
  - Commandes : `node scripts/noyau-file.mjs [list | put <fichier> | get <nom> | path | delete <nom>] [projet]`.
- Suivi systématique Todos (outil : `node scripts/noyau-todo.mjs [list | add <texte> | comment <ref> <texte> | prompt <ref> <texte> | report <ref> <modifs> | status <ref> review | find <recherche>]`, référence courte `*XXXX` visible sur chaque carte et cliquable dans la conversation) : pour chaque prompt utilisateur demandant une évolution ou un bug :
  - Si nouvelle tâche : créer/ajouter automatiquement un todo dans le projet/dossier concerné.
  - Dès qu'une tâche est traitée/corrigée par l'agent : utiliser `report <ref> "modifications effectuées"` — il ajoute un commentaire daté avec le commit courant puis passe la tâche au statut « À tester / valider » (`status: review`, `[/]`). L'agent valide lui-même son suivi : à la fin de chaque tour, Noyau coche aussi les tâches que la réponse finale déclare livrées, preuve citée à l'appui (`server/todo-autoclose.js`). Avec la section « À valider » active la tâche y passe, sinon elle passe en `done`.
  - Si la tâche existe déjà : ajouter un commentaire horodaté **très concis** (une phrase, 200 caractères maximum) sur le todo existant.
- Pages de suivi (onglet « Suivi » du projet) : chaque agent tient son tableau prévu / en cours / décision fondateur / fait + KPI + rapports via `node scripts/noyau-board.mjs [list | show | set | kpi | add | ask | move | done | edit | rm | report] ...` (`help` pour la syntaxe). Une décision Go/Non du fondateur notifie l'agent propriétaire.
- Tri fichiers partagés (bouton « Trier » de la section Fichiers) : l'agent « Tri fichiers partagés » passe UNIQUEMENT par `node scripts/noyau-file-sort.mjs [scan | trash <nom> --reason R [--duplicate-of N] | keep <nom> --reason R | finish] --project <id>` ; corbeille restaurable 30 j, fichiers < 48 h et uploads fondateur protégés.
